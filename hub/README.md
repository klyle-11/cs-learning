# hub — a markdown reader with a notes layer

Reads any folder of `.md` files, however deeply nested. `.html` files are rendered as they are, in a frame. Source files (`.c`, `.h`, `.cpp`, `.py`, … and `Makefile`) are listed too and shown as code. Nothing in here is specific to one topic.

```
cd hub && npm start                       # http://localhost:4321, reads ../data   (the same as ../start.sh)
../start.sh path/to/other/folder          # or point it somewhere else
PORT=4400 npm start                       # run two environments at once
npm run start:network                     # reachable from a phone: HTTPS and pairing, see below (HOST=0.0.0.0)
npm run start:network:insecure            # the network WITHOUT encryption: only on a network you fully control
npm run start:https-local                 # HTTPS even on this computer
npm run start:pair-local                  # this computer's own browser must pair too
npm run start:scratch                     # the scratch workspace (../data-test) on port 4396, with its own state
npm run cert                              # make or renew the certificates and print the fingerprint
npm run cert:new-authority                # replace the authority; every device then installs the new one
npm run build        npm test             # build the server; run its checks
```

On Windows every one of these has a twin ending in `:win` (`npm run start:win`, `npm run start:network:win`, …); see `../WINDOWS.md`.

`npm start` runs `../start.sh`, which starts the server, `../server-cpp/hubd`, building it first if needed. This folder holds only the page; npm is used for the page's libraries and nothing else (the document engine among them, from its package in `../marginalia-engine-integration/`).

The server answers this computer only unless started with `HOST=0.0.0.0`. Then it speaks HTTPS (it makes its certificates on that first start), prints a pairing code, and each device goes through two steps once: trust the hub's certificate (open `http://<address>:4321/` on the device and follow the page), then type the pairing code. On the computer the hub runs on, `http://localhost:4321` keeps working with nothing installed. `../CERTIFICATES.md` explains what trusting that certificate means; `server-cpp/API.md`, "Security", has the details.

`../data` is the live workspace and is not in git. The first run creates it as a copy of `../sample`, the starter content that is. Delete `data/` to start again from the samples.

## Using it

- **Files** (left): the folder tree. Folders start closed, every time the reader is opened; the ones you open stay open for that visit. A closed folder's line carries a small button naming what was last opened inside it: press it to go straight back there without opening the folder. An open folder is as long as what is in it (the list is the one thing that scrolls): its own line stays at the top while you scroll through it, and while a top-level folder runs off the bottom, the line of the next top-level folder is held at the bottom edge; press that to jump past. A single click opens a file in place of the one you were previewing (its tab title is in italics). A double click opens it as a tab that stays, so both are open. Double-clicking a tab also keeps it.
- **Find**: the box above the file list. As you type it narrows the list to files whose name or title matches, and lists those files under the box; the folders in the list are not opened by it, and stay as you left them. From three letters on it also looks inside the documents and in your notes, and lists the lines found; pressing one opens the document at that place. In a file of saved links it looks in each item's name and addresses, and pressing what it found opens the gallery at that item's card, or its row in the table of pages. Without the server it searches the copies kept on the device. The × at the end of the box, or Escape, clears it. (On a touch screen the reader as a whole is not zoomed by a pinch or a double tap; a pinch on a picture or a video makes that one larger, and text has A−/A+.) The main front page has, over its title, "Latest searches", closed until pressed: for each thing looked for, the one result you opened from it (the last, if you opened several); pressing a line opens that result again, × forgets it. Kept on the device, 30 at most.
- **Where you stopped**: a document opens at the place you last left it, also after the reader has been closed. Kept on the device, per workspace, for the 300 most recent documents. A PDF drawn by the reader is kept as its page and how far down that page, so it holds on a screen of another width; a folder’s page is gone back to as well. Another device has its own places.
- **Back**: the ‹ at the start of a pane's tab bar (or Alt + ←) returns that pane to what it showed before: the gallery after a picture, the page a link was followed from, the tab you switched away from. It is remembered for the current visit only. With nothing left to return to, it goes up a level at a time: the front page of the folder the document is in, then the folder above, ending at the main front page. Held down (or pressed with the other mouse button), and from the small ▾ beside it, it lists the latest opened, newest first: press one to return to it.

**Tabs**: opening something takes the place of the tab being looked at, so tabs do not pile up; what was there is one press of back away. A tab is added only on purpose: a double click, or the + on a file's line. On a phone, the + at the end of the tab bar opens the list to choose from, and what is pressed there opens in a tab of its own. Something that already has a tab is gone to, not opened twice.
- **Second document**: the "side" button on a file row (or Cmd/Ctrl/Alt-click), or "open on right" in the tab bar, opens a document in the right-hand column, which it shares with the notes. Drag the column's left edge for width and the bar between document and notes for height; "move notes above/below" swaps them. Closing its last tab gives the column back to the notes. Closing everything returns to the front page. The layout is remembered.
- **Reading aids**: the sidebar icon beside the title tucks the sidebar away (hover or click the strip on the left edge to bring it back). In the settings (the gear beside the title): "reading focus" fades everything except the paragraph under the pointer or at the reading line; "roomy text" widens line, word and paragraph spacing; A−/A+ change the text size. A thin bar under the tabs shows how far through the document you are. Keyboard focus always has a thick outline, and file rows and tabs work with Tab and Enter.
- **Upload a folder**: the folder icon at the end of the file list's first line (the workspace's name, where the # for a group and the + for adding files are too) picks a folder from your computer and asks where it goes. *Add to this workspace* copies it in as a new folder beside the others; files that already exist are left alone, never overwritten. *Open as its own workspace* copies it to `hub/workspaces/<name>/` and switches the hub to it, with its own notes, title and tabs. Nothing is deleted: the workspace menu that appears above the file list switches back. Dot-files, `node_modules` and files over 50 MB are left out. A file that fails does not stop the rest: the others are still sent, and the ones that were not saved are named, with their size and the reason, when it finishes. Only the server going out of reach, or an answer that every file would get (not paired, storage full), stops it early. Several folders can go up together: drop them on the sidebar at once, or press "add another folder…" in the dialog after choosing the first (a browser's folder chooser gives one at a time); each joins the workspace under its own name, with its own FRONTPAGE.md, a copy of its README.md, or a new front page.
- **Removing a folder**: "remove folder…" on a folder's front page takes the folder and everything in it out of the workspace, after asking. It is deleted on the server and for every device; files on your own computer are not touched.
- **Locked folders**: tick "Lock this folder" when uploading a folder, or press "lock…" under its page (its front page, or the gallery or list made for a folder that has none; "update…" and "remove folder…" are there too). The folder keeps its line in the file list, where it was, marked "locked"; the reader shows nothing of what is in it (not in the list, in what is found, the galleries, the player or the queue) until its password is typed. There is one password for all locked folders: it is chosen when the first folder is locked (or first opened), every folder locked after that takes the same one once it has been typed, and typing it opens the one folder it was typed for: the others stay locked until each is opened itself. It is asked for again each time the reader is opened and after ten minutes in the background; "lock now" hides it at once. It works without the server too. This is a lock on the reader, not encryption: the files are stored as they are, and removing the folder and uploading it again takes the lock off. Needs HTTPS or localhost.
- **Other hubs**: the reader can also look at a hub running on another machine. In the settings, under Hubs, "add a hub…" takes a name and that machine's address; the other hub then asks this device for a pairing code (made on that machine, in its reader, under "devices…"), once. After that a menu at the top of the sidebar switches between this hub and the others; notes, uploads and everything else go to the hub being looked at. Each hub's copies are kept on this device under that hub, so they open with that hub off, and "everything on this device…" (settings, under Connection) lists what is kept from all of them, by hub, and opens any of it. The list of hubs is kept by the hub the reader was loaded from, so its other devices see it too; each device pairs with each hub itself. Nothing is found automatically: an address is typed once. From another hub, pictures, music and video are fetched whole before they show (no streaming), HTML pages are shown without their own pictures and styles, and changes made elsewhere appear within a minute rather than at once. A hub reached over HTTPS must have its certificate trusted on the device (its address followed by `/trust`).
- **On a phone** (screens under 760px): one document at a time. "☰ Files" and "Notes" in the top bar slide the sidebar and the notes in over the page; tap outside to close. To open something beside what is already open, press the "+" at the end of the tab bar and choose from the list (anything in it: a file, a book, a folder's line, something found), or press the "+" on its line: a file's, a book's, a gallery's, or a folder's (which opens the folder's page: its front page, or the one made for it). To save a note, press "Save note" over the right end of the note box (shown on a phone and on any touch screen; Enter still saves where the keyboard sends it). The note box stays at the bottom at the height you leave it; drag the small handle above it to resize, or press the handle to switch between small and about a quarter of the screen. Selecting text shows the highlight menu just below the selection.
- **Contents dial**: whenever the sidebar is hidden (always on a phone), a small icon sits at the top right of the page. It opens a short scrolling list of the document's headings in tiny text; the one at the centre is selected and drawn large. Scroll to turn the dial, tap the selected heading to jump to it, or tap another heading to bring it to the centre. In a book the dial is the book's, as the outline is: every page of the book by name (tap the selected one to open it), with the headings of the page being read under its name. Tap the icon, outside the list, or press Escape to close.
- **HTML pages** open in a frame, looking as their author made them. Headings feed the outline and the contents dial, and selecting text gives the same highlight menu and notes as markdown, with highlights drawn in the page. A page's own scripts never run, in the reader or when the file is opened in a tab of its own, and it cannot load anything from the internet.
- **PDFs** appear in the file list (under Documents on a front page) and are drawn by the reader itself with PDF.js: every page, one under the other, with − and + for their size and the page number in the bar. **Words on a page can be highlighted and written about**, as in any other document: double-click a word (on a touch screen, double-tap it or press and hold), drag either of the two handles to take in more, then pick a highlight type from the swatches or press "note". With a mouse, pressing and dragging selects as well. Pressing a highlight opens it (change its type, write a note, remove it), and a highlight in the notes panel brings its page into view. A selection stays within one page. What reads a page's text and finds a highlight's words again is the document engine (`marginalia-engine`, in a worker of its own); it is given the file after the first pages are showing, so selecting works a moment after the PDF opens, and a scanned PDF (pictures of pages) has no words to select. "theme" in the bar gives the pages the pane's theme: its paper and its ink, with pictures left in their own colours, and they change with the theme. Off, the PDF is as it was made. It is on under a dark theme and off under a light one until pressed, and then stays as chosen. "reader" in the bar hands the PDF to the browser's own viewer, in a frame, and back, and stays as chosen: there nothing can be highlighted, the button is "night" (dark pages by turning the colours inside out, pictures too), and a phone's browser has no such viewer (an iPhone shows the first page only). "open in new tab" still hands the file to the device's own viewer. A PDF can be kept on the device like a picture. A kept PDF is drawn by the reader itself when the server is out of reach (and so is a PDF on another hub): the same pages, read from the copy on the device a piece at a time. What draws them (PDF.js) is kept by the service worker with the rest of the page, so the reader has to have been opened once with the server in reach after this was added.
- **A PDF on a phone**: its bar (smaller and larger, theme, reader, keep) is put away so the pages have the room; the button with two sliders in the top bar brings it out and puts it back. The page being read ("page 7 of 120") is on the PDF's tab.
- **The note box** is a card that floats over the foot of the page (on a phone, a strip along the foot of the screen) and not a band of its own under it: the page scrolls behind it, and can be scrolled clear of it at its end. A frame (a book's page, the browser's PDF viewer) ends above it instead. On a phone it is lifted over the keyboard.
- **#fav**: the "#fav" button over the note box puts what is open in the group `#fav` in one press (the highlight or note being worked on, if there is one), and takes it out again; it is dark while what is open is in it. While items are being picked for a group ("#" beside Files), "#fav" puts what is picked in it. It is a group like any other, listed with the others, and anything can be in several groups at once: what is in #fav can be picked into another group later and stays in both. The main front page lists what is in #fav under the latest notes and highlights.
- **More room to read**: the small button before "In:" over the note box puts the tabs (and on a phone the top bar) away; press it again to bring them back. While they are away a small muted gear lies over the page's top left corner (it brings the bars back and opens the sidebar at its settings), and beside it, for a PDF, − and + for the size of its pages and the page being read ("page 7 of 120"). Where a viewer's own bar still shows (a PDF's, on a desktop), the gear sits under that bar and not over it, and the size and the page are left to the bar, which has them already. The note box stays, so the button is always there.
- **The queue**: each line has four buttons to move it: to the top, one up, one down, to the bottom.
- **Changing what plays**: pressing a track while another is playing asks first (keep playing, add to the queue, or play it instead), since a line is easily pressed by accident. With nothing playing, or while paused, a press plays at once; next and previous never ask.
- **Pictures and video** open in a viewer. In the file list a folder's pictures and videos are one line, its gallery (the folder's own line when it holds nothing else; a "Gallery" line above its other files when it does): pressing it opens them as cards. A folder's sound files are one line the same way, its music page. A folder with a front page has no lines apart from it: the front page lists the folder's pictures, videos and music under its description, and opens on them. So a folder of nothing but pictures, videos and sound files (with or without a front page) is a single line in the list (a folder's line like any other, with what was last opened or played in it to press at its end, but no arrow, as there is nothing to open out), and a folder opens out only when it also holds documents or folders: to its front page (or else its "Gallery" and "Music" lines) and its other files. While finding, each file that matches is listed. A picture fits the pane; click it, or press "full size", to see it at its real size, and "open in new tab" hands it to the browser. A picture inside a document opens in the viewer when clicked. On a phone the viewer (and a gallery of saved links) is a lightbox: it takes the whole screen, the top bar and the tabs out of the way, with the note box below it; its bar has "notes" (the notes drawer) and × (back to where the pictures were opened from, however many were stepped through). A picture at its real size there fills the screen: the note box goes, the bar, the arrows and the reel lie over the picture, and the browser's own bars are put away where the browser can do that (not on an iPhone). It stays so while stepping to the next; tap the picture or "fit to window" to return, × to close.
- **Music**: pressing a sound file plays it where you are, without leaving what you are reading; the controls appear at the foot of the sidebar, the playing track is marked in the file list (on its folder's line for them, since a folder's sound files are that one line; the tracks themselves are listed on the music page, each with its queue button), and its name in the footer opens the player in the right-hand pane, beside what you are reading; pressed again with the player already there, it opens in the main pane (a double click, or "+", opens it too). The player's playlist is every sound file in the folder grouped by where it lives. Opening the player does not start or change what is playing. "previous" restarts the track, and goes to the one before if pressed again; music keeps playing while you read. **Queue**: the queue button on a sound or video row (in the player, the file list, a front page listing, or the video viewer's bar) lines it up; the queue is listed under the player's controls, and under the small controls in the sidebar (three rows at a time, the rest by scrolling); in either place a row can be played or taken out. Next and previous step through the queue, or through every sound file while it is empty. Shuffle puts the queue in a random order (queueing every track first if it is empty). The repeat button cycles: repeat the queue (the default), repeat this song, no repeat. A queued video plays in the pane if a video is on show there, and otherwise in the background, sound only. A video that is playing also carries on (sound only) when you open something else, and is still playing when you come back to it. Either way the small controls sit in the sidebar: back and forward ten seconds, play/pause, and a link back to what is playing. On a phone, volume is the device's own.
- **Books are one thing**: an `.epub` is listed by the server as its pages (cover, contents, chapters, index), and the reader folds them back into one book wherever files are counted or chosen from: a folder's tiles and lists, the counts in the settings, "on this device only", and what is found by name (a book found by a chapter's name opens at that chapter). On a folder's page, books and PDFs are a shelf: a card each with its cover (a book's first picture, a PDF's first page, drawn when the card comes into sight), pressed to open it; a book opens where it was last read. A book's page reads as the reader's own documents do: the pane's colours, the reader's typeface, text size and column, and "roomy" and "focus" from the same controls.
- **A book's cover goes with it**: the tab of a book or a PDF carries its cover before its name (a book's first picture; a PDF's first page). While one is being read its cover is also at the top right of the page: in the margin beside the text on a wide pane, and as small as the contents button, beside it, on a narrow pane or a phone. Pressing it goes to where the book begins (a PDF: its first page). A PDF shown by the browser's own viewer has the cover on its tab only. In the file list, the line of a book, or of a folder that is one line (a book's folder, an album, a shelf), has its picture in place of the sign of its kind, where it has one: its cover, else the first picture in it, else the cover of the first book in it.
- **Where a book opens**: at the page last read in it; the first time, at its contents if it has a page of them (a page named "Contents" or "Table of Contents", or a file named `toc` or `contents`; for a book that names neither, the page among its first eight that leads to the most other pages of the book, four or more, looked for once in the background and remembered on the device; else a file named `nav`), and not at its cover. This is the same wherever the book is opened from: its line in the file list, a card, or what was found by name.
- **Scrolling through a book**: at the end of a page of a book, scrolling on turns to the next part, and at the top, scrolling back turns to the one before (it opens at its end). A turn takes a push of its own: the scroll that arrives at the end, and its momentum, turns nothing; stop, then scroll on (a touch: a drag that starts at the end). By touch the push is read three ways, any of which turns the page: the finger moving on at the end, the finger lifted further up than it came down, and (on an iPhone) the page pulled past its last line. Space, Page Down and the down arrow do the same at the end; Page Up and the up arrow at the top. At the end, a small label names what comes next; pressing it turns too. Each part is still a page of its own, with its own progress bar. "scroll through books" in the settings turns it off; the arrows at the sides stay.
- **A folder's name in the hub**: when a folder is uploaded, the dialog asks for its "Name in the hub", offering the name it has on its disk. Type another and it goes by that here: two folders called "Music" from two drives can be kept apart, and a name already in use is said to be (the files would join that folder). "update…" still finds the folder it was uploaded from, whatever either is called.
- **Updating an uploaded folder**: an uploaded folder is a copy, and the server watches the copy, not the folder it came from. "update…" on the folder's front page brings the copy up to date: the folder on the device is read again (names, sizes and dates only), the server says what the copy holds, and only what is new or was changed since is sent, a changed file replacing its copy. Nothing is removed from the copy. In Chrome and its kin on a computer the reader remembers which folder it was (for folders uploaded from now on, and after the first update of an older one), and asks only for leave to read it; elsewhere the folder chooser is shown each time. Hidden files and files over 50 MB are left out, as on upload. The same press on a folder inside an uploaded one updates just that part, if that folder is the one chosen.
- **Sets: folders of albums, authors, seasons**: a folder whose folders are each one line already (an album, a shelf of books, a single film), with or without such files of its own beside them, is one line as well, and never a folder of notes. Its page (its front page, else one made for it) shows a card for each folder in it: a picture from inside (its cover, else the first picture in it, a video's first frame, a book's cover or a PDF's first page), its name, and how much it holds ("12 tracks"; pictures beside other things are not counted). Pressing a card goes into that folder; where the folder is nothing more than one thing and has no front page, straight to the thing. The folder's own files are listed on the page too, before the cards if there are more of them. This goes as deep as the folders do (music, then artists, then albums). A one-line folder's line is lit while anything inside it is being read or played, and Back goes up through these pages one at a time. A page made for a folder goes by the same name as its line. A folder that holds a single text document and has no front page opens that document, with no page before it.
- **The look follows you**: the theme, the typeface and the reading settings are each device's own, kept in its browser. They are also sent to the server when one is changed, and a browser that has made no choice of its own (one that was cleared, or forgets when it is closed; the reader opened at another address; a new device) starts from what the server has. A device's own choice is never overruled.
- **Every folder has a page**: its front page, else one made for it, showing the folders in it as cards and its own files listed (whichever there is more of first). The file list still opens a folder of notes out; the page is the way into it from a card or from the pages above, and on a phone, where the list is out of sight.
- **The outline is a panel of its own**: a tinted ground to the sidebar's edge, a heavier line over it and a sign before its name; its text is lighter and quieter than the files' (no bold: the levels are told apart by how far in they sit), with a rule down its side that the place being read lights up.
- **Fewer presses to anything**: the workspace's front page has a library under its description: every folder at the top of the workspace as a card, under the same headings as the file list (Pinned, cs-learning, then each kind), so any of them is one press from the front page with nothing to open out. A card for a folder with sound in it has a play button: everything in it is lined up and the first track starts, without going in. Over the title of a folder's page are the pages above it, from the front page down, each one press away. A folder's page shows what is in it on arriving: one kind of thing is simply listed, with no tile to press; several kinds open on everything unless the folder holds more than 80 things, or on what the page was last left on. "group by folder" is offered only where what is listed is in more than one folder. In the file list the kinds stay open or closed as they were left, from one visit to the next (the folders in them start closed, as before). What is done to a folder (update, lock, remove) is under its page, not over its title. A picture, a video or a sound file goes by its name without the ending; a book's card says EPUB or PDF, since the same book may be there as both.
- **Pinning a folder**: a folder's line in the file list has a pin at its end (it shows when the line is pointed at; on a touch screen, faintly, always). A pinned folder is listed under "Pinned", over the kinds: a folder at the top of the workspace moves there, one inside another is listed there as well as in its place. Press the pin again to unpin. Pins are kept with the layout, on this device.
- **Keep from the tab**: the tab of what is being read carries the keep mark (the same one as in a viewer's bar): press it to copy that file to this device, press again to remove the copy. On a page of a book it stands for the whole book.
- **Partly on this device**: the settings also count the books and folders that are only partly kept: a book with some of its pages, or a folder with some of its documents, of its music, or of its pictures and videos (the three counted apart, so reading one document in a folder of videos does not make the videos partly kept). The line opens to the list, each with how far it has got ("3 of 12 music"; a book by how much of it is here, "30% of the book", since what a book is kept as is not a count a reader has) and, with the server in reach, a "finish" of its own; "finish them all" fetches whatever is missing from every one. Nothing is recorded for this: it is counted from what is kept, so a "keep all" that was cut short shows as far as it got and is carried on from there.
- **Without the server**: a line appears above the file list when the server is out of reach; the settings (the gear) show the details under "Connection". Opening a document does not copy it to this device: a copy is made when asked for, with the keep mark (only front pages are kept as they are read, being the way around without the server; and a copy that is already kept is brought up to date when the document is opened). The marks: (● in the file list; ○ means server only; press the mark to keep or remove a copy; in the settings, "keep all documents" copies the text and HTML pages "keep all music files" the music and "keep all pictures and videos" those, each separately; a picture or video also has a keep button in its viewer's bar and on its gallery tile). If the server goes away you can keep reading those, and notes and highlights you make wait in a queue and are sent when it returns. "add files…" (or dragging files onto the sidebar) puts files in `inbox/`; added while disconnected, they show ↑ until sent. The page itself is kept too (a service worker, `sw.js`): the reader opens at once from that copy, with the server near or absent, and offers "a newer version is ready" when the page has changed on the server. So it opens, reloads and starts from the home screen with the server off; it then shows what is copied to this device. This needs HTTPS (or localhost), and one visit with the server on after an update to the page. Nothing kept on the device expires by itself, however long the server has been away. A browser may still clear a site's storage when the device runs short of space; the reader asks it not to, and the privacy box says whether it agreed ("Kept here"). Installing the reader (Add to Home Screen, or Install) is what most reliably makes a browser keep it; in Safari on an iPhone, a site that is only a tab and has not been opened for a week is cleared, an installed one is not. What is kept opens whole: a page of a book, or an HTML page, is kept with the stylesheets and pictures it names (a book's are inside the book), and a markdown document with its pictures; shown from the copy, the styles are written into the page and the pictures point at their copies. Fonts are not kept (the reader takes a font from the server only), so a book that brings its own shows in the reader's. Pages kept before this are completed once, quietly, the next time the server is in reach. A file of saved links still needs the server, and the web, to show its media.
- **Privacy box** (settings, under "This device"): how this device is connected (this computer only, encrypted, or not), which paired device the server takes it for ("devices…" lists them, removes them, and makes a code to add another), and whether the copies kept in this browser are encrypted. "protect…" encrypts them with a passphrase: it is asked for each time the reader opens, the reader locks itself after ten minutes in the background, and a forgotten passphrase means the copies here are removed and fetched again (only unsent changes would be lost). Needs HTTPS or localhost.
- **Changes the server refuses** are not dropped quietly: one it may accept later (storage full, not paired) stays in the queue and is retried; one it never will is listed in the status box until dismissed.
- **Problems** appear bottom right as a plain sentence, with the technical details folded underneath.
- **File list**: the main front page comes first, under the reader's title. Its line carries three buttons at its end: # (make a group), + (add files) and upload a folder. **Inbox** (where added files go) is a line of its own with nothing to open out: its page shows everything in it, of any kind, as cards, the latest changed first. While a copy of something is being made on this device, a thin bar along the foot of its line or card shows how much has arrived (for a book, how many of its pages). Then the starter material, together in one folder line named "cs-learning", closed until pressed like any other folder: the top-level folders and files named in `hub.json` under `"starter"`. The other top-level folders (the ones that were added) are listed under six kinds, by what is inside them, everything in a folder counted: **Notes** (more than half of what is in it is markdown, its folders' contents counted too; a book counts as one thing), **Mixed**, **Audio**, **Video**, **Image/video galleries**, **Books and documents**. Each kind is one line, closed until pressed, with a count; a kind with no folders is not shown. Pictures do not make a folder mixed (a cover beside an album, the figures of a text), but a folder of nothing but pictures is a gallery, and so is one whose files are files of saved links (any such file counts, whether what it points to is media or only pages: the list of files does not say which). Under a kind each folder is a section by itself, `inbox/` (where "add files…" puts things) first among them, then the rest with the one most recently added to first (by the newest file in each), and loose files come last. Every folder's line, at any depth, begins with a small sign of its kind. A folder that comes down to one thing (one file, or one book, in it or in the one folder it holds, and so on down; front pages apart) is one line with nothing to open out. Pressing it opens the folder's page: its front page if there is one on the way down, else a page made for it. Either shows the thing as a card beside the title and description, with a picture (the folder's cover, else the picture itself, a video's first frame, a PDF's first page, or the first picture in a book's opening pages, else the sign of its kind); pressing the card, or its Open / Read / Play, opens the thing in a tab of its own, a book where it was last read. A shelf is one line the same way: a folder that comes down to two or more things with no folder among them, each a book, a PDF, a picture, a video or a sound file (an album; the same book as an `.epub` and as a PDF). Its page (the front page on the way down, else one made for it) opens on what is in it: the tracks, the pictures, the books as cards, with the folder's cover beside the title. Otherwise, a folder that holds nothing but one folder is that folder's line: both names on it ("outer / inner"; once, if they are the same), and what it opens or opens out to is what the inner folder holds. A picture named `cover` (`.jpg`, `.png`, `.webp`, `.gif`) in a folder is that folder's cover: it is not listed or counted as a file anywhere (so a folder holding only a cover is not listed at all), and it is shown beside the title on the folder's page (its front page, or its gallery or music page). An open folder does not scroll inside itself; the next folder's line, held at the bottom edge, is the way past a long one (see "Files" above). The Outline label names the document the outline is of.
- **References in a note**: type `//` in the note box (no space after it) and a link button appears on every file in the list, every heading in the outline, every note and highlight in the notes, and every track, picture and video in a listing. Pressing one writes a reference where the `//` was; press as many as you like. Typing anything else (a space, say), saving the note or Escape takes the buttons away. A reference is stored in the note's text as `[label](path)`, `[label](path#heading)` or `[label](path#note:id)`, the path counted from the top of the workspace, and shows as a link that opens the document, goes to the heading, or shows the highlight.
- **Latest notes and highlights**: the main front page has a box in its right-hand corner listing the fifteen most recent notes and highlights from every document, newest first, each with its date and document. Pressing one opens the document at that passage. In a narrow pane the box sits above the page instead of beside it.
- **Where a highlight belongs**: a highlight remembers more than its words: which block of the document it is in (by a hash of the block's letters and digits), how far into it, and the characters on either side. So the same words highlighted in two places stay in their two places, and a highlight keeps its place when text is added above it. If the words are no longer in the document, the note says "not found in this document as it is now" and is kept. Highlights made before this are placed at the first occurrence under their heading.
- **Books (EPUB)**: an `.epub` in the workspace is one line in the file list. Pressing it opens the page last read in it (the first, to begin with), and the mark at its end keeps every page on this device. The outline lists the book's chapters in reading order, with the open page's own headings under its chapter. While finding, the pages that match are listed in the file list. A page opens like any HTML page, with its pictures and styles, and can be highlighted and annotated the same way; links between pages stay in the reader. With the server in reach, a page is drawn from the document engine: rebuilt from what is allowed (no scripts, forms or frames), with every HTML entity resolved, and read from the book's file a piece at a time, so a large book is never fetched whole. Its highlights are then found again by the engine (by their words, the words around them and their place in the book), and a highlight made before this is given the engine's anchor the first time its page is opened. Without the server, or on another hub, a page is shown as the server sends it, as before. A book's page takes the colours of the pane's theme and the reader's text size (A−/A+), where other HTML pages keep their author's look. The server reads the pages straight out of the book's file. A faint arrow at each side of a page (or the left and right arrow keys) goes to the page before or after, in the book's reading order. Not yet there: search inside books.
- **Stepping through pictures and videos**: with a picture or video open, an arrow at each side of it (or the left and right arrow keys) goes to the one before or after in the same folder, in the order the gallery shows them. A reel under it shows up to four on either side; press one to jump to it. In a folder's gallery the cards are in columns, each the shape of its picture, with the same size slider; a video's card and its place in the reel show its first frame. The bar says which one of how many is showing.
- **A page that is a program**: an HTML page's own scripts do not run in the reader. To let one page run (a tool of your own, such as `scripts/grid.html`), list its exact path in the workspace's `hub.json`: `"scripts": ["scripts/grid.html"]`. It then works as it does opened by itself, with its file pickers and drops, but kept apart from the reader: it cannot see your notes or ask the server for anything, it has no outline or highlights, and its own settings are not remembered between visits. Such a page may load things from the web.
- **Saved links as a gallery**: a text or JSON file with web addresses in it (an export of saved media, a list of direct links, a browser's bookmark export) is listed in the reader. Opening it lists what it holds, as text, and loads nothing; "Show the pictures and media" then shows it as a gallery like a folder of pictures: a grid of thumbnails, each opening a viewer with arrows (and the arrow keys) to the one before and after and a reel of those nearby. Everything in the file is shown, however much there is. Three filters sit beside the slider: a menu to show only pictures, only video, only webm (`.webm` clips are a type apart from video) or only sound; for a JSON file, a menu of the entries its items have (thumbnail, video (full), webm, picture (full), sound, page, linked page, source page: those the file has), to show only the items with that entry; and a box to show only what has the typed words in its name or in any of its addresses (the table of pages is narrowed by the words too). "sort" puts the cards in order of their names (pressed again, back to the file's order) and "shuffle" in a random order. A saved item that holds several addresses (its thumbnail clip, the media itself, the page it links to, the page it was found on) is one card with those listed under its picture: pressing one shows that picture or plays that media in the card, pressing it again puts the card back, and a page opens in a new tab. The viewer's bar (the one with "close") has the exact address of what it is showing, a link that opens it in the browser, and under the bar every address that item groups is listed in full (thumbnail, video, pages), each a link, with the one on show marked. Only an address that is a media file itself (by its ending: the picture, video and sound types a browser shows or plays, or a `format=`/`mime=` in it; an address with `.mp4` or another media type anywhere in it, such as `…/394826.mp4/?rnd=1`, counts too) is drawn or played as a card; an address that is a web page, under whichever name it was saved, is listed as a page. "reverse" turns the order round, last in the file first, for the grid, the list and the table of pages; it is remembered. The grid is shown 60 cards at a time, in columns, each card the shape of its picture; a slider sets how wide the cards are (and so how many fit across), and is remembered. A see-through list at the side names everything in the file, marks what is on the page being shown, and jumps to any of it ("list" hides it). In the viewer, pressing a picture shows it full size, and pressing again fits it to the window. Pressing a thumbnail opens the viewer; the address in the viewer's bar is that of the media itself, and is what opens in a new tab. A card with a video also has a play button (not one whose thumbnail is a clip already playing by itself; open that one in the viewer): it plays the video in the card, with its controls, one at a time (starting another, the × on the card, turning the page or opening the viewer puts the picture back), and with its sound in step when that was saved at an address of its own. The size slider and the page buttons stay at the top while the grid scrolls. A video with no picture of its own shows its first frame; a `.webm` clip plays silently in the grid while in sight and starts by itself in the viewer. In an export of saved items the direct addresses are what plays, and a `.webm` clip saved as the item's thumbnail is its moving thumbnail (or is the media itself, if nothing else is listed); a video file of another kind saved there (an `.mp4`) is taken for the video itself, a direct address, not a thumbnail. An item with its video and its sound as separate addresses gets a player for each. Addresses that are only pages come under the gallery in a table (name, site, address), sorted by site. The gallery takes the colours of the pane it is in. On a front page, under "Saved links", each such file is one card: pointing at it lists what is in it, pressing it opens the gallery inside the card. The media is loaded from the sites it is on, by a page the server makes in a frame apart from the reader, and only when asked: those sites then see this device's address (see `REVIEW.md`, "Files of saved links").
- **Focus groups**: a list of items under a name of your choosing, `#name`. Press `#` beside Files, then `+` on anything that belongs together (files, folders, headings in the outline, notes and highlights, pictures, videos, tracks), type the name and save. Under the name the groups there are already are offered as marks to press, five at a time, the latest first; typing narrows them to the names that have what was typed in them, and pressing one writes its name, so what is picked joins that group (the button then reads "add to it"). The main front page lists every group, the most recently made or added to first; pressing one lists what is in it. A music queue can be saved as one from the player ("save as a group…"). Groups sit at the top of the file list as small marks, `#name` and how many are in it, one after another and wrapping; what is in a group is listed under the marks only once its mark is pressed, and pressing it again puts the list away. Press an item to go to it; × takes it out; a group with music or video in it can be added to the queue. Saving under a name already in use adds to that group. Groups are kept on this device, not on the server.
- **Theme and font**: in the settings (the gear beside the title). Themes are Plain, Selenized Light, Pale Lime, Pale Sky, Lime Night and Sky Night (the same two at night: deep green and deep blue paper, with the golden sepia turned light), Eva Night (navy), Triple-M (dark purple, sepia-gold accent, pink for small marks), Sun Sound (the whole reader is one colour that moves through hot pinks and oranges over three minutes, with near-black text), Periwinkle (pale lavender with deep indigo ink and touches of gold) and Mahogany (deep red-brown with silver ink and accents, and cobalt for small marks and pressed buttons); each is a block of colour tokens at the top of `index.html`. "one theme" beside the menu, while pressed, gives the whole reader that theme. Released, the left pane (files and outline) and the right pane (the side document and notes) can each be given a theme of their own from the same list, in the two menus beside it; "same" follows the reader's. What the two menus were set to is kept while "one theme" is on.
- **Outline** (left, below the files): headings of the document that has focus; click to jump.
- **Highlighting**: select text and a small menu appears. Click a colour to highlight (that colour stays in use until you pick another), or "note" to highlight and write about it. Click an existing highlight to change its type, annotate it or remove it.
- **Notes** (right) and the box along the bottom belong to the document that has focus. While a highlight is selected, the line above the box shows which one you are annotating. The legend at the top of the notes panel renames and recolours the highlight types.

## Starting a new learning environment

1. Make a folder for the topic's documents, anywhere, and start the hub on it: `./start.sh path/to/folder`.
2. Copy `CLAUDE.md` and change its first paragraph to describe the new topic.
3. Write a `FRONTPAGE.md` (title and description) and add markdown files.

## Folder specification

```
<topic>/
  FRONTPAGE.md      landing page: its first `# Heading` is the title, the rest is the description
  hub.json          settings
  sources/          what you are reading — any folder names work
  responses/        write-ups Claude produces in answer to your notes
  references.md     log of everything cited
  notes/notes.json  your notes (written by the reader; don't hand-edit while it is open)
  CLAUDE.md         instructions for Claude in this folder
  hub/              this app
```

Only `FRONTPAGE.md`, `hub.json` and `notes/` are fixed names. Every markdown and source file under the folder is listed, grouped by its directory. Dot-folders, `node_modules`, `notes/` and `hub/` are skipped.

### FRONTPAGE.md

Optional. The one at the top of the workspace is shown when the hub opens and whenever you close the last document. Its first `# Heading` is the title in the sidebar and browser tab (renaming the title in the sidebar rewrites that line); everything after it is the description.

Any folder can have its own `FRONTPAGE.md` as well. It appears first in that folder in the file list, as "Front page". Uploading a folder offers to use the one it has, copy one of its markdown files, or make a new one.

Under the description, every front page shows a row of tiles (Everything, Documents, Pictures and video, Music) counting what is in that folder; pressing one lists it. Lists show everything together with each item's folder beside it; "group by folder" splits them up.

All front pages are editable in the reader with "edit front page". They are the only documents the reader writes.

### hub.json

```json
{
  "title": "Discrete Maths",
  "side": ["references.md", "responses/"],
  "ignore": ["CLAUDE.md"]
}
```

- `title` — shown in the sidebar and browser tab. Only used when there is no `FRONTPAGE.md`.
- `highlights` — the highlight types, each `{ "id", "name", "color" }`. Managed from the legend above the notes; four defaults are used until changed.
- `side` — files, or folders ending in `/`, that open in the second pane when linked to.
- `ignore` — file names, paths, or folders ending in `/`, left out of the reader.

### Markdown files

- The first `# Heading` is the document's title in the picker.
- `#`, `##`, `###` headings make up the table of contents.
- Links to other files in the folder (relative paths, optional `#heading-slug`) open inside the hub as a tab; files listed under `side` open in the other pane. Relative image paths work. A heading's slug is its text lowercased with each run of non-letters/digits replaced by `-`.
- Fenced code is coloured by the language on the fence (` ```c `, ` ```cpp `, ` ```python `, …); a fence with no language stays plain. Source files are coloured by their extension.
- A blockquote containing a paragraph that starts with bold `**Answer…**` hides everything from that paragraph on behind "Show answer".

### Notes

`notes/notes.json` is an array of:

```json
{ "id": "…", "doc": "sources/file.md", "heading": "slug", "headingText": "Heading",
  "quote": "pinned text span or empty", "type": "highlight type id or empty", "text": "the note, empty for a bare highlight",
  "ts": "ISO time", "status": "highlight | open | answered",
  "reply": "markdown, optional", "replyDoc": "responses/file.md#slug, optional" }
```
